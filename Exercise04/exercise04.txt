3. EXPLANATION AND LIMITATIONS
-----------------------
Both programs got faster in this dataset. Pi scaled almost linearly,
consistent with independent sampling and little shared work. Sum's
short runtime makes communication and variation more significant.
These are interpretations of these measurements.

Timers include computation and result reductions, but exclude MPI
startup, the initial barrier, printing and timing aggregation.
The nodes are different instance types: t2.large and t2.micro.
Burstable CPU conditions and node differences affect performance.
Process counts do not establish the number of physical cores.

All sums equal 50000005000000.
Pi: P=1 3.1416776000; P=2 3.1413084000; P=3 3.1417304000.
Fixed rank-specific seeds repeat estimates at a given process count.
Changing process count changes streams; speedup does not imply accuracy.

The sheet's timing reference to exercises 1 and 2 is interpreted as
the two computational tasks, sum (Exercise02) and pi (Exercise03),
because Exercise01 is repository creation.
